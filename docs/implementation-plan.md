# Implementation sequence

Only Part 1's executable prompt is included in this starter package. The stages below guide later prompts; they are not instructions to implement everything now. Each later task must read the shared specification and preserve completed work.

## 1. Foundation and verified content

Create the static-export application, typed content, honest project status/links, asset paths, route skeletons, source-of-truth instructions and basic checks. No deployment or elaborate motion. Completion: type/lint/build checks succeed; all known routes export; real images/PDF work; absent links are omitted; no fictional content.

## 2. Visual system, navigation and responsive shell

Implement tokens, typography, semantic navigation/mobile menu, shared footer, accessible controls, responsive spacing and contact paths. Resolve the font through a legitimate source with a system fallback. Completion: keyboard and touch use work; focus/menu behavior is sound; text/background contrast verified; no copied reference assets.

## 3. Portrait-led opening

Create the actual wide/narrow portrait-and-name compositions using the supplied image. Establish hero/intro hierarchy before adding scroll movement. Completion: 360–1920px checks, no face or name clipping, no image stretching, useful static/no-JS presentation, image quality assessed honestly.

## 4. Work index and project overviews

Implement three featured projects, five-project index, reusable overview pages, honest private/sign-in/live labels and missing-media treatments. Completion: visitor can distinguish products and contribution scopes; no broken demo/repo links; all pages directly accessible. Upgrade to deep case studies only when technical decisions/evidence arrive.

## 5. Story, experience, services and contact

Integrate the concise homepage narrative and expanded About page; employment and education from final CV; two service categories; direct contact. Completion: no invented awards/dates/Go project, equal employment/freelance contact paths, CV opens, January 2027 wording consistent.

## 6. Coordinated motion

Add scoped GSAP/ScrollTrigger behavior, restrained hero movement, project hover/focus treatments and selected reveals. Completion: native scroll preserved, reduced-motion is complete, content remains visible after failures, fast/reverse scroll and resize work, no listener/trigger accumulation after navigation.

## 7. Browser, accessibility and performance validation

Test real static export, keyboard, mobile, screen sizes/zoom, JS-disabled content, reduced motion, links, missing media and asset sizes. Check root and prefixed deployment paths. Record what actually ran; fix findings rather than claim perfect scores. External-link failures should be reported, not treated as proof the service is permanently down.

## 8. GitHub Pages release and handover

Use actual repo and confirmed Pages/domain settings. Configure checks and deployment with documented Actions, correct path configuration, truthful metadata and a real 404. Enable publication only when owner chooses to release. No fabricated canonical URL or automatic DTO launch. Document updates to project status, availability, assets, CV and future case studies.

## Release inputs still pending

- Project screenshots and permission for any private-interface/architecture detail.
- Confirmed public GitHub profile and intended domain, if used.
- Optional concrete Go/personal project.
- Specific decisions/results for deeper case studies.
- Review of project labels and current availability at publication.

None requires another general career questionnaire or prevents Part 1.
